First public release.

YealinkMonitor is a macOS menu bar app that watches a fleet of Yealink handsets
through the YMCS Open API v2 and tells you when one goes offline.

**[Documentation](https://tony-nz.github.io/YealinkMonitor/)** ·
**[Getting started](https://tony-nz.github.io/YealinkMonitor/documentation.html#first-run)**

## Install

Download `YealinkMonitor-0.1.0.zip`, unzip it, and drag `YealinkMonitor.app` into
`/Applications`. The build is signed with a Developer ID certificate and
notarized by Apple, so it opens without any Gatekeeper ceremony.

Open **Settings** from the menu bar item and enter your YMCS Client ID and
Secret, then press **Save & Test Connection**. To set up further Macs without
retyping anything, use `Scripts/provision.sh`.

To look at the app before you have a tenant, launch the demo fleet:

```
/Applications/YealinkMonitor.app/Contents/MacOS/YealinkMonitor -demoFleet YES
```

## What is in it

- Menu bar item showing how many phones need attention, with a popover listing them
- A window with a sortable, filterable table and a per-device detail pane
- Notifications on confirmed outages and recoveries, with debouncing, quiet hours and per-device mutes
- Email alerts over SMTP, batched so one network fault sends one message
- YMCS alarms shown alongside this app's own view, since a phone can be reachable and still have a critical alarm against it
- Accessory health, so a phone with a dead expansion module stops looking fine
- Per-device diagnostics run on the phone: ping, traceroute, system log, config file, screenshot and packet capture
- Call quality with MOS scores, and the YMCS operation log, in an Activity window
- Restart phones: one, a selection, or everything currently listed — and on a schedule
- On-disk history of status changes, so you can see which phones drop repeatedly
- CSV export of whatever the window is showing
- A demo fleet (`-demoFleet YES`) that makes no requests and reads no credentials

## Requirements

- macOS 14 or later. Universal: runs natively on Apple Silicon and Intel.
- A YMCS subscription with API access, and a Client ID / Secret pair.

## Worth knowing

- **The YMCS AccessKey is an enterprise-wide write credential.** It authorises
  device restart, factory reset, firmware push and configuration push across
  every phone in the enterprise, and YMCS issues one pair per enterprise, so it
  cannot be scoped down for this app alone.
- **Factory reset is not implemented and will not be.** The reset endpoint
  differs from reboot by one path segment and takes an identical body, so the
  protection against firing it by accident is that no code here can express it.
- **Scheduled restarts only fire while the app is running and the Mac is awake.**
  That is a property of a menu bar app, not something this code can work around.
- **Detection latency is bounded by YMCS, not by this app.** Phones report in on
  their own schedule; the detail pane shows `lastReportTime` so you can see how
  stale YMCS's own view is.

## Not included

App Sandbox. Configuration push and firmware push are deliberately left out;
firmware is read-only, and the table marks a phone running an older build than
the rest of its model and stops there.
